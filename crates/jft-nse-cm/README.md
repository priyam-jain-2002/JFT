# jft-nse-cm

Authoritative Rust data plane for NSE Cash Market Order and Trade data.

This crate owns source integrity, layout dispatch, fixed-width framing/parsing, exact jiffy handling, canonical events, lifecycle reduction, order-book replay, reconciliation, quarantine, and deterministic output hashes.

Python must consume the versioned canonical artifacts emitted by this crate. It must not parse raw NSE Order/Trade bytes or maintain a second authoritative order book.

Implemented evidence-backed slices currently cover locked, audited MD5/SHA-256 digests and payload-based record identity; explicit manifest v1 Rust types, deterministic compact JSON plus terminal LF, strict major-version/unknown-field rejection, source/compressed/trigger/payload/processing evidence validation, and a reviewed language-neutral JSON Schema with byte-identical golden output; content-based empty/gzip/ZIP/ASCII/unknown-binary signature detection; strict CM Full/Trim filename decoding; homogeneous stream-set discovery without a fixed stream count; exact data/trigger stream-member pairing; logical-delivery orchestration with nested errors; deterministic multi-delivery inventory discovery with exact filename rejections; exact LF framing with borrowed corrupt-tail evidence; lazy byte-addressable outcomes over caller-provided source bytes; current Trim/Full and historical Full 87/100/101 Order/Trade layout maps; validated date dispatch including the one-day Full exception and Trim introduction; date-dispatched Full structural framing plus per-field observed-byte profiles with exact source-byte/residue reconciliation; strict Trim field parsing; an order-only entry/modify/cancel reducer with isolated `PO`/`RM`/`CA` identities and non-mutating cross-session anomalies; checked price-level projection from active orders with typed empty/one-sided/normal/locked/crossed top-of-book evidence; caller-ordered single-source and validated independent stream-set Trim Order replay with exact active/entry/failure provenance, count reconciliation, and member-aware successful-transition observers without merging streams; checked combined Order summaries that retain stream context and delivery identity; both-sided single-source Trim trade-reference classification plus all-stream candidate collection, reconciled multiplicity/side/raw-jiffy-relation diagnostics, a streaming observer for each successful Trade with exact source and complete buy/sell candidate evidence exposed through both raw profiling and the composed report builder after fail-closed delivery validation, and a deterministic one-pass in-memory Order/Trade evidence report with per-source jiffy sequences and within-/cross-kind range-overlap pairs with fail-closed delivery identity, checked Order/Trade summaries and `PO`/`RM`/`CA` counts, deterministic session-excluded successful-entry occurrence groups and rejected cross-session lifecycle candidates with deterministic operation/session-route counts and raw-jiffy before/equal/after relations, exact quarantine/framing evidence with optional independently validated raw quarantine jiffies plus a deterministic borrowed Order/Trade stream-provenance view with exact failure-class and validated-jiffy-availability counts plus a deterministic zero-copy Order/Trade framing-loss view with checked per-stream framed/residue byte accounting against independently recorded caller source lengths and a deterministic borrowed lifecycle-anomaly dossier, and a per-stream nonzero observation taxonomy, all without resolving equal-jiffy or cross-stream order; and standalone Order/Trade jiffy range/tie/regression profiling across exact paired-delivery members with deterministic stream ordering and pairwise range-overlap evidence. Filesystem enumeration, profiling on representative current data, Full semantic parsing, durable canonical transition output, disk-backed input/decompression, production trigger-file parsing/manifest persistence, Python manifest conformance, temporal/cross-stream replay ordering and checkpoint hashes, validated session transitions/daily reset, trade-driven quantity semantics, and canonical columnar output are not implemented yet.
